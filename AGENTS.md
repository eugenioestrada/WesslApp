# Technical decisions

## Architecture

- Keep `Wessl.Domain` limited to dependency-free models and interfaces. Do not put platform APIs, process execution, or UI concerns in this project.
- Keep WSLc process integration, JSON parsing, and Windows-specific launchers in `Wessl.Infrastructure`.
- Keep composition, lifecycle, polling, and container actions in `Wessl.App` services. Keep UI components small and composable.
- Build the UI declaratively in C# with Microsoft.UI.Reactor and WinUI 3. Do not introduce XAML or MVVM/ViewModels.
- Prefer built-in .NET and Windows App SDK APIs; add third-party dependencies only when they are necessary.

## Localization

- Use Windows App SDK MRT Core resources (`.resw`) for user-visible strings; do not introduce a separate localization package or `.resx` pipeline.
- Store one `Resources.resw` per BCP-47 language tag under `src/Wessl.App/Strings/<language-tag>/`. English (`en-US`) is the default and Spanish (`es-ES`) is also supported.
- Keep resource keys and format placeholders consistent across language files. Add new visible text to every supported language resource instead of hardcoding it in UI or services.
- Resolve app strings through `AppStrings` and the PRI generated by the Windows App SDK build.
- The app is unpackaged, so Windows selects resources using the system display language rather than the preferred-language list. English remains the default fallback.

## Runtime and integration

- The app is an unpackaged WinUI 3 desktop app with the Windows App SDK runtime included. It targets Windows SDK 10.0.22621.0, requires Windows 10 build 19041 or later, and supports x64 and ARM64.
- Register `SampleWslcClient` by default for safe demo behavior. Use `WslcClient` only when explicitly enabling the real WSLc CLI integration.
- Keep asynchronous work and external process interactions out of UI components; marshal UI updates through the app's dispatcher.

## Validation

- Build the solution with `dotnet build Wessl.slnx`.
- Run tests with `dotnet test tests/Wessl.Tests/Wessl.Tests.csproj`.
